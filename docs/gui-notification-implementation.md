# GUI 区域通知修复

## 已实施

| 场景 | 当前处理 |
|---|---|
| 窗口在前台且未最小化 | 勾选“弹框”后发送系统通知，不再使用自动 Toast 替代 |
| 窗口失焦、最小化或隐藏到托盘 | 勾选“弹框”后同样发送系统通知，不主动抢焦点或打开窗口 |
| 通知总开关关闭 | 保留日志和最近事件，不自动发送 Toast/系统通知 |
| 首次命中 | 立即提醒 |
| 同一 IP、地区及请求路径持续命中 | 每 60 秒最多提醒一次，查询 API 变化不重复触发 |
| IP、地区或请求路径改变 | 提醒最新事件；全局最短 3 秒，短时间变化合并为最新事件 |
| 恢复未命中 | 结束当前命中状态并取消待发送提醒；再次命中可立即提醒 |
| 停止或重新启动监测 | 取消旧任务定时提醒，发送前及前端均检查任务身份 |
| 自动断网完成后停止 | 允许同一任务已经产生的最终命中通知送达，并标记实际保护结果 |
| 系统通知调用失败 | 保留未读状态及最近事件，错误日志限频；后续有效命中按原节流规则再次尝试，或由用户手动查看历史 |
| 托盘查看最近提醒 | 显示“历史提醒”、原发生时间及最近命中状态，不改写成当前发生时间 |

区域事件使用独立的结构化回调，包含任务、事件、IP、地区、路径和保护状态，不再根据日志中的英文字符串判断是否弹框。相同命中过程保留首次发生时间，另记录最近观测时间。

2026-10-21 按用户确认调整：勾选“弹框”后，所有窗口状态统一使用系统通知；切回前台不再自动重放 Toast 或清除未读状态。托盘“查看最近提醒”仍是用户主动打开的应用内历史提示。首次命中、60 秒持续命中提醒和变化事件最短 3 秒合并规则保持不变。

普通用户和 PAC/WPAD 降级继续遵循仅告警策略；通知明确展示权限不足或系统路由出口，不会在操作成功前声称已经断网。内容跟随界面语言，系统通知外观由操作系统控制。

开始/停止按钮改为等待真实后端结果，执行期间互斥并禁用重复操作；成功后提示成功，失败提示具体错误。普通提示仍默认 2 秒，区域与操作失败提醒为 6 秒。Toast 共用组件，最多同时显示 5 条，移除时清理定时器。

## 实现位置

- `internal/guiapp/monitoring/match.go`：发布经过有效性检查的匹配观测。
- `internal/guiapp/notifications.go`：去重、定时合并、发送通道、任务隔离、历史记录及未读状态。
- `internal/guiapp/events.go`：仅处理日志和状态事件，不再从日志触发区域通知。
- `cmd/netgapgui/frontend/src/composables/useAppState.js`：焦点/可见性同步、通知状态合并及过期事件过滤。
- `cmd/netgapgui/frontend/src/components/ActionPanel.vue`：等待开始/停止结果并管理加载状态。
- `cmd/netgapgui/frontend/src/composables/useNotification.js`：统一 Toast 队列、去重与清理。
