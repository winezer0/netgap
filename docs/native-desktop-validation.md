# 桌面验收执行指南

本文件说明桌面和网络验收的执行方法，不维护通过/待验收状态。当前状态与证据分别集中在[已验证场景记录](已验证场景记录.md)和[剩余未验证场景记录](剩余未验证场景记录.md)。

## 验收环境

原生构建工作流：`.github/workflows/native-build.yml`。构建矩阵包括 Windows amd64、Ubuntu 22.04/24.04 amd64、macOS Intel/Apple Silicon。额外验收只通过手动 `workflow_dispatch` 触发。

真实默认路由变更只在具有快照和独立控制台的隔离测试环境进行。命令行版是路由切换的验收入口；GUI 与 CLI 共用底层路由操作函数，不单独执行真实路由切换。

## 执行步骤

1. 下载同一成功 CI 运行的目标平台产物和证据，核对提交号与架构；Linux 保持 `netgap-gio-proxy` 与程序位于同一目录。
2. 在隔离测试会话中使用全新临时配置，先确认自动删除路由关闭，再启动普通监控场景。
3. 使用本地代理和 PAC 服务；逐 URL 核对系统解析结果、重定向目标和实际请求路径。
4. 测试网络变化或系统代理配置时，只操作隔离测试机。监听器故障使用可重复的原生故障注入，不能用共享状态机单元测试代替。
5. 路由删除前创建虚拟机快照并确认控制台可用；覆盖双栈、多网卡、部分失败、重启恢复及绑定冲突。
6. 记录环境、步骤、预期、实际结果及恢复状态。未执行项不要填写通过。

## 部署注意事项

- Linux CLI/GUI 需将 `netgap-gio-proxy` 放在程序旁，并安装 GIO/glib-networking、桌面代理 schema 和对应 PAC 模块。Ubuntu 22.04 的 libproxy 0.4 需要 `libproxy1-plugin-webkit`；Ubuntu 24.04 GUI 使用 WebKit 4.1 和 `webkit2_41` 构建标签。
- GUI 默认开启自动删除路由。普通用户应先关闭该选项再启动监控；Linux/macOS 修改路由要求有效 root 权限，当前没有自动提权功能。
- `--recovery-check --recovery-dir <原快照目录>` 只预检权限、快照格式和恢复存储，不修改路由；实际恢复仍需校验网络绑定、冲突和有效期。
- 删除默认路由不是完整网络隔离：直连网段、更具体的路由、VPN `/1` 路由和系统重新生成的路由仍可能保持连接。
