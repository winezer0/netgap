# 已验证场景记录

本文是项目已验证行为的唯一汇总。只记录实际执行过的场景，并注明验证边界；实施计划和操作方法见各自指导文档。

## CLI 路由删除与恢复

- **Ubuntu WSL 实际路由**：CLI 执行 `--shutdown-test` 删除 IPv4 默认路由，随后 `--recovery-check` 与 `--recover` 成功；IPv4/IPv6 路由状态与验证前一致。只操作 WSL 网络，没有操作 Windows 主机网络。
- **Ubuntu CI 隔离网络命名空间**：[运行 39438905192](https://github.com/winezer0/netgap/actions/runs/39438905192) 在 Ubuntu 22.04/24.04 使用 CLI 删除并恢复 IPv4/IPv6 默认路由，runner 原网络命名空间前后未变。
- GUI 路由操作与 CLI 共用 `iproute.DeleteAllDefaultRoutes`、`RestoreAllDefaultRoutes` 及对应受保护操作函数；按验收约定，真实路由切换只覆盖 CLI。

## 系统代理解析与监控

- **Linux GNOME/KDE**：WSL 私有 D-Bus、临时配置和本地 PAC 服务覆盖固定代理、绕过、PAC、逐 URL 选路、缺少解析后端时报错，以及 PAC 服务退出后恢复并重新取得代理候选。
- **Windows WPAD 不可用回退**：手动 CI 验证不可用 WPAD 时使用静态代理，并验证其他 WPAD 错误不会静默直连。
- **macOS 网络监听恢复路径**：手动 CI 在 Intel/ARM runner 验证监听器失效标记后的重启与恢复路径。测试没有制造真实 SystemConfiguration 服务故障。
- **监控并发与健康状态**：Windows/WSL race 测试和压力测试覆盖停止后旧查询不覆盖新任务、失败退避期间仍可查询，以及查询健康与路由失败状态分离；压力测试包含 200 次重启及 10,000 轮加速故障/恢复检查。
- **恢复存储预检**：覆盖损坏、旧版本、空路由、非默认路由快照拒绝；并发存储探测不替换原快照；Linux 普通用户对不可写目录的删除/恢复预检明确失败且保留快照。

- 手动原生 CI [运行 39501195921](https://github.com/winezer0/netgap/actions/runs/39501195921) 的 Windows、Ubuntu 22.04/24.04、macOS Intel/ARM 五个平台均通过；验收步骤仅由手动 `workflow_dispatch` 触发。
- 五个平台的 CLI/GUI 原生构建、核心测试、归档检查通过。更早的 [运行 39431157549](https://github.com/winezer0/netgap/actions/runs/39431157549) 还检查了 10 个实际安装归档；内层归档摘要见[归档摘要附录](safe-acceptance-native-2026-10-20.md)。

- Windows Go 全量测试、选定核心 race 测试，Linux/WSL 八个核心包 race 回归，前端 18 项测试与 ESLint，以及 actionlint 均通过。各批次详细测试命令和证据链接见本记录对应 CI 或[实施记录](proxy-route-repair-progress.md)。
