# Windows 路由恢复修正记录

日期：2026-10-21。

## 删除后恢复失败

`CIM result 4` 表示调用参数无效，不能解释为必须等待几秒。此前把所有 `[In]` 字段都当作必填项的判断不成立。

后续扩展错误已定位本次实际失败字段：`Invalid parameter ValidLifetime ... Microseconds: 61603`。原实现用 100ns 精度扣除经过时间后，将余下的微秒传入 NetTCPIP，导致有限生命周期恢复被拒绝；此前仅验证无限生命周期，未覆盖此问题。

现已将 ValidLifetime 和 PreferredLifetime 向下取整到整秒，两者共用同一计算时间，微秒字段保持为 0。不足一秒的有效期按已过期拒绝恢复，首选期允许降为零，无限生命周期保持不变。新增覆盖用户日志数值、有限首选期、不足一秒、过期、无限值和系统时间回退的回归测试。此修正不需要固定等待，也不延长原路由有效期。

本次按本机 `MSFT_NetRoute.cdxml` 的 `ByInterfaceIndex` 参数集构造创建请求：使用接口索引，不同时传接口别名，不填充未使用的可选字段。ActiveStore 明确传入策略存储；持久恢复保留默认创建行为及已有的活动路由副作用日志。恢复仍校验接口 GUID、网络身份、隔离舱和属性，失败时保留剩余快照。

对不同网络隔离舱的记录提前拒绝操作，避免省略隔离舱输入后恢复到错误的网络上下文。此限制不等于已支持跨隔离舱恢复。

错误信息现在区分参数实例构造、参数写入、结果拉取和提供程序失败，并读取提供程序的扩展消息。没有新增固定等待或对参数错误的自动重试。

## 未删除时点击恢复

不存在快照时返回明确的无操作结果。GUI 显示“没有待恢复的路由”，CLI 的 `--recover` 提示无需恢复。操作前的检查与删除串行，不需要管理员权限即可完成无快照检查。快照损坏、读取失败、格式不兼容仍返回错误并保留文件。

## 验证与限制

- Go `internal/iproute`、`internal/guiapp`、`cmd/netgap` 测试通过。
- Windows 本地 CIM 参数构造、类型回读及与系统 CDXML 参数集的核对通过；没有调用创建或删除方法。
- 前端 26 项测试及 ESLint 通过，覆盖无快照、正常成功和真实错误的不同提示。
- 路由包 Linux amd64、macOS amd64、Windows arm64 交叉编译通过。
- 前端生产构建通过。
- Windows amd64 GUI 原生构建通过：`cmd/netgapgui/build/bin/netgapgui-recovery-fix.exe`。未清理原程序或恢复快照。
- 生命周期修正版：`cmd/netgapgui/build/bin/netgapgui-lifetime-fix.exe`，应使用此版本替代上一个修正版。

真实 IPv4/IPv6 创建、持久/活动存储恢复、立即恢复及重复恢复仍需在隔离 Windows 环境验收。上述安全检查不能证明系统提供程序已实际完成恢复；当前宿主机及 WSL 路由未改动。
