# 代理与断网保护修复计划

## 目标与边界

修复审查报告中的 5 项 P1、3 项 P2，优先保证检测持续有效、断网操作可继续、路由可完整恢复。

沿用已确认要求：每个查询网址按系统固定代理、PAC/WPAD 或直连规则选择实际路径；触发断网时删除所有网卡的 IPv4/IPv6 默认路由，完整保存恢复信息。

本文件仅规划工作，不修改业务代码、不执行测试或真实断网操作。审查中的风险仍需在实施阶段逐项确认。

## 第一阶段：先修复路由保存与恢复基础

涉及：`internal/iproute/snapshot.go`、`snapshot_windows.go`。

1. **拆分路由身份与可变属性（P1）。**
   - 身份包含稳定网卡标识、目标前缀、下一跳及存储类型；接口索引仅用于当前操作时定位。
   - 同一身份只保留一个恢复目标；新捕获的有效状态更新旧属性，历史记录不同时参与恢复。
   - 兼容已有 v2 快照，加载时识别并整理重复记录；无法消解的冲突保留并明确报错。
2. **修复持久路由恢复语义（P1）。**
   - 区分临时与持久路由的创建参数，按真实 cmdlet 约束实现。
   - 将同一路由在 ActiveStore/PersistentStore 中的关联状态作为整体处理，避免创建持久路由附带的活动记录与后续恢复互相冲突。
   - 操作后读取两个存储确认结果；仅移除已确认恢复成功的备份。
3. **收紧到相关网络的校验范围（P1）。**
   - 校验稳定网卡、网络身份、相关地址族及下一跳适用性。
   - IPv6 临时地址等无关变化不阻止 IPv4 恢复；实际切换网络仍拒绝恢复旧路由。
   - 分开定义查询结果有效性、断网续作范围和恢复适用性，避免共用一个过严的指纹。
4. **移除命令行中的大数据载荷（P2）。**
   - 固定 PowerShell 脚本，结构化数据通过标准输入传递；保持超时、取消、错误输出与资源清理。

完成标准：已有快照可读取；重复捕获不产生冲突恢复目标；临时与持久状态可分别确认；部分失败不丢备份。

## 第二阶段：修复部分断网后的持续执行

涉及：`internal/iproute`、`internal/monitor/monitor.go`、`internal/guiapp/monitoring/manager.go`。

1. **增加明确的断网任务状态（P1）。**
   - 状态至少区分：监控中、准备完成、断网待重试、断网完成、等待重新检测。
   - 修改路由前持久保存任务范围和恢复信息，记录未完成目标；完整备份与待删除清单分开维护。
   - GUI 与 CLI 使用一致的执行规则。
2. **续作不依赖重新取得公网 IP。**
   - 进入待重试状态后，先处理任务中的剩余路由，再安排出口查询。
   - 已删除路由视为完成；失败采用有上限间隔的退避，显示剩余数量和原因。
   - 不使用删除前的全局路由指纹阻止续作，因为应用自己的删除也会改变该指纹。
3. **限制旧任务的作用范围。**
   - 每次续作校验具体路由和相关网络身份，只处理原任务确认的目标。
   - 网络变化或出现新路由时重新检测，再决定是否建立或扩展任务；不沿用旧 IP 结果删除新网络路由。
   - 停止监控、关闭自动断网、替换监控实例时停止后续重试；保留恢复信息。
   - 重启发现未完成任务时显示可恢复状态；只有保护重新启用且校验通过后才能续作。
4. **成功以实际结果为准。**
   - 完成前再次枚举默认路由，发现新增项时转入重新检测，不误报全部断网成功。
   - 日志和界面区分出口查询失败、部分断网、重试暂停、全部完成。

完成标准：主路由已删且 API 不可达时，仍可处理原任务的剩余目标；停止操作及时生效；旧任务不会删除新网络路由。

## 第三阶段：修复代理路径可用性

涉及：`internal/ipchecker/checker.go`、`proxy_transport.go`、`internal/detector/proxy.go`、`proxy_routes.go`。

1. **拆分 PAC 和候选路径预算（P1）。**
   - 为规则解析、单候选连接和整体查询分别设置有界预算。
   - 单候选连接超时后，在整体预算内尝试下一条系统授权路径；候选数较多时合理分配剩余时间。
   - 保持 PAC 原顺序；仅在规则明确包含 DIRECT 时直连，不为规避错误擅自绕过代理。
   - 明确区分连接阶段失败、请求发送后失败和用户取消，避免扩大回退条件。
2. **环境变量按目标网址解析（P2）。**
   - 先判断绕过规则与目标协议，再验证实际选中的代理。
   - 无关协议的错误变量不阻止查询；被 NO_PROXY 绕过的目标不因未使用的代理格式错误而失败。
   - 继续保持系统规则与环境变量的既有优先级，避免隐式改变路径选择。

完成标准：首个代理无响应时，后续合法候选有执行机会；取消及时结束；结果中的路径与实际成功路径一致。

## 第四阶段：平台能力与回归边界

1. **处理非 Windows 功能回退（P2）。**
   - 先核对项目声明的支持平台。
   - 若 Linux 仍受支持，补齐其完整快照、删除、恢复及互斥实现，满足“所有默认路由”的既定要求。
   - 若项目明确仅支持 Windows，启动保护前展示平台能力并拒绝不可执行的配置。
   - 平台范围不明确时，先确认选择，再实施相关分支。
2. **同步文档和错误分类。**
   - 更新支持矩阵、任务状态、备份兼容行为和错误恢复说明。
   - 保留具体失败原因，避免以“监控运行中”掩盖断网操作失败。

## 建议验证方案（获得测试授权后执行）

| 范围 | 关键场景 |
| --- | --- |
| 保存与恢复 | 临时/持久路由、双栈、多网卡、同身份属性更新、旧快照、部分恢复失败、重复执行 |
| 断网续作 | 首条删除成功后其余失败、API 不可达、停止/重启监控、关闭自动断网、并发手动恢复、新网络出现 |
| 网络绑定 | 无关地址变更、相关子网变化、网卡索引复用、下一跳变化、应用自身删除触发网络通知 |
| 代理路径 | 固定代理、PAC/WPAD、首候选拒绝/无响应、多个候选、显式 DIRECT、重定向、取消与整体超时 |
| 环境规则 | HTTP/HTTPS 分别配置、错误的无关变量、NO_PROXY、配置中途变化 |
| 容量与平台 | 大量路由和地址、命令输入失败、Linux 能力行为 |

优先进行内存后端与本地代理模拟；真实路由删除、持久存储及重启后恢复在隔离 Windows 环境验证。模拟测试通过不能替代真实 cmdlet 的行为验证。

## 实施顺序

1. 路由身份、快照兼容、持久恢复、网络绑定和输入通道。
2. 基于上述基础实现 GUI/CLI 断网任务与独立续作。
3. PAC 时间预算与环境代理逐网址解析。
4. 平台能力处理、文档及授权后的回归验证。

每阶段独立形成可审查变更，记录已解决问题与未验证限制。第一、二阶段完成前，不将完整断网与恢复能力标记为已修复。
