# 代理与断网保护实施计划

本文保留实现约束和验收方法，不记录当前问题状态。当前通过与待验证场景分别见[已验证场景记录](已验证场景记录.md)和[剩余未验证场景记录](剩余未验证场景记录.md)。

## 目标与边界

- 查询每个网址时按系统固定代理、PAC/WPAD 或直连规则选择实际路径；错误配置不能被隐式直连掩盖。
- 触发断网保护时保存并处理所有网卡的 IPv4/IPv6 默认路由；恢复时验证网络绑定并保留失败备份。
- Windows、Linux 和 macOS 是目标平台。GUI 与 CLI 共用检测与路由底层逻辑；真实路由操作使用 CLI 验收。
- 删除默认路由不等于完整网络隔离。不得在日常主机网络或无恢复控制台的环境执行真实断网操作。

## 实施要求

### 路由快照与恢复

涉及 `internal/iproute` 和平台路由后端。

1. 将稳定路由身份与可变属性分开；接口索引只用于当前操作时定位。
2. 区分临时与持久路由，并检查创建、删除和恢复后的活动/持久存储状态。
3. 根据稳定接口、相关地址族、子网和下一跳验证网络绑定；无关地址变化不应阻止恢复，真实切网应阻止恢复旧路由。
4. 大型结构化数据通过标准输入传递给固定脚本；错误、取消和超时须可区分。
5. 变更前持久保存完整恢复数据；部分失败保留未完成项，不能覆盖冲突路由或丢失备份。

### 部分断网续作与监控

涉及 `internal/monitor`、`internal/guiapp/monitoring` 和 `internal/iproute`。

1. 将断网任务与出口检测分开调度；旧任务仅能操作其原授权目标。
2. 删除失败后采用有上限的退避，同时保留出口查询机会；新查询不得扩大旧任务范围。
3. 停止、关闭保护或替换监控实例时取消后续动作；旧运行不能覆盖新运行状态。
4. 分别记录查询健康和路由保护进度。只有核对实际路由状态后才报告保护完成。
5. 重启后读取未完成任务时校验网络身份、冲突和有效期；无效快照保留并给出可操作错误。

### 代理路径

涉及 `internal/detector`、`internal/ipchecker` 与 `internal/ipchecker/proxy_transport.go`。

1. 分离规则解析、单候选连接和整次查询预算；保持候选顺序，不添加系统未授权的 DIRECT。
2. 每个 API 和重定向目标按 URL 重新应用协议规则及绕过规则。
3. 用户取消、连接阶段失败和请求发送后的失败分别处理；请求发送后不能因超时换用其他路径。
4. 环境代理只有在系统规则允许时作为后备；未使用的代理配置错误不能阻断被绕过的网址。

### 平台后端与运行身份

- Linux 使用 Netlink 处理路由及网络变化；GIO/libproxy 助手与程序并排部署，并按当前桌面会话身份读取配置。
- macOS 使用 CFNetwork 和原生路由接口；同步原生调用的取消边界要明确，网络监听需释放旧资源并有界重建。
- Windows 使用系统代理解析和 NetTCPIP 路由接口；恢复需同时考虑活动和持久存储。
- Linux/macOS 修改路由需有效 root 权限；GUI、CLI、普通用户与管理员的恢复数据目录须明确。

## 验收方法

- 自动化测试覆盖路由快照、身份冲突、取消、失败退避、快速停止/重启、PAC 候选和系统选路错误。
- CLI 真实路由删除/恢复只在有快照和独立控制台的隔离环境执行；记录 IPv4/IPv6 路由变化及恢复结果。
- 代理切换用受控代理和 PAC 服务，逐 URL 核对实际请求；监听故障使用平台原生注入。
- GUI 验收覆盖启动、设置持久化、日志/健康状态、停止重启和生命周期；真实路由切换不重复测试 UI。
- 结果只写入[已验证场景记录](已验证场景记录.md)或[剩余未验证场景记录](剩余未验证场景记录.md)，本计划不另存状态副本。
