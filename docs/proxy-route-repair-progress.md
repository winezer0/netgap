# 代理与断网保护实现说明

本文说明当前实现的模块职责和关键行为，不维护问题是否解决或场景是否验收的状态。验证状态统一见[已验证场景记录](已验证场景记录.md)与[剩余未验证场景记录](剩余未验证场景记录.md)；设计目标见[修复计划](proxy-route-repair-plan.md)。

## 代理检测与系统选路

- 每个 API 及重定向目标按目标 URL 解析系统代理规则，候选顺序遵循系统配置。只有系统规则明确包含 DIRECT 时才使用直连；配置读取或解析失败会返回错误。
- Linux 通过相邻的 `netgap-gio-proxy` 调用 GIO/libproxy。助手输出有大小上限，缺少依赖或解析失败不会静默退回环境代理。
- Windows 读取当前用户系统配置；macOS 使用 CFNetwork。Linux 桌面代理、macOS 网络状态由平台后端读取。
- 查询、配置快照和路由校验沿调用上下文执行。不能取消的原生同步 API 在返回后检查结果是否过期。

## 监控与断网续作

- GUI 与 CLI 共用监控、查询和路由后端；每次运行有独立身份和取消上下文，旧任务不能更新新任务状态。
- 断网任务固定原授权的路由范围和网络身份。部分失败时按退避继续处理；查询出口失败或处于退避期间仍可继续检测，但新结果不会扩大旧任务范围。
- 查询健康与路由保护状态分别记录，避免一次成功查询掩盖尚未完成的路由动作。
- 停止监控或关闭自动保护会取消当前动作和后续续作，保留恢复数据。手动恢复会使旧续作失效。

## 路由快照与恢复

- 快照记录默认路由、接口和网络绑定信息；恢复前检查当前网络、路由冲突和存储状态，部分失败时保留未完成备份。
- Linux 使用 Netlink；macOS 使用原生路由套接字；Windows 使用 NetTCPIP PowerShell 接口并核对活动和持久存储。
- `--recovery-check --recovery-dir <目录>` 只检查快照和恢复存储，不执行路由修改。
- 当前快照格式为版本 3；旧版本不会自动导入。普通用户与管理员运行时可能使用不同数据目录。

## 运行边界

- 默认路由删除不等于防火墙隔离；更具体路由、直连网段、VPN `/1` 或系统重建路由仍可能保持连接。
- Linux/macOS 路由修改要求有效 root 权限；程序不自动提权。
- CI 中的 UI 启动冒烟覆盖包启动链路；真实路由切换按验收约定只由 CLI 验证，GUI 与 CLI 共用底层路由函数。
