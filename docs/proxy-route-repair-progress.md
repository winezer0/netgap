## 断网任务的行为

- 变更前持久保存全部恢复数据和任务范围；已消失的目标无需再次删除，仍在的目标继续处理。
- 部分失败后，无需取得新的公网 IP 即可继续原任务。每次恢复任务都重新核对原目标、相关网络和代理指纹。
- 出现原任务之外或属性已变化的默认路由、网络绑定变化或代理规则变化时，任务失效，转回出口检测；不直接扩大删除范围。
- 停止监控或关闭自动断网会取消当前动作与后续续作，恢复数据保留。重新启用保护后可加载未完成任务，校验通过才执行。
- 手动恢复先使断网任务 ID 失效，防止旧续作再次删除已恢复路由。监控仍启用时，之后新的有效区域命中仍可创建新断网任务。
- 读取损坏的任务备份会报告错误，但不阻断出口检测；不覆盖或忽略损坏备份执行删除。

## 当前边界

- Windows 系统路由操作不是事务；外部进程仍可在核对后改变路由，代码通过逐条检查、最终复核及保留备份限制影响。
- Windows 的持久创建遵循 [New-NetRoute 的 PolicyStore 约束](https://learn.microsoft.com/en-us/powershell/module/nettcpip/new-netroute#-policystore)。活动副作用的恢复流程尚未在真实系统执行。
- Linux 不改 NetworkManager 等持久配置；网络管理器可能重新生成默认路由，新路由必须重新检测。无法绑定接口的默认路由（例如部分下一跳对象配置）会在删除前明确拒绝，不能宣称所有 Linux 路由类型已覆盖。
- Linux 对链路重连/机器重启采取保守拒绝旧绑定策略；同一网络重连也可能需要由网络管理器重新获取路由。无关地址变化不再作为全地址集合精确匹配的失败条件。
- macOS 同样保守校验启动会话、链路及相关子网，不修改网络服务持久配置；网络管理器重新创建路由不被视作旧任务授权。ARP/NDP 及流量生成的克隆主机路由不进入网络配置指纹。管理员组身份不足以修改路由，需要有效 root 权限。
- PAC 连接预算上限为 1.5 秒，按当前请求剩余时间与候选数缩短；整体仍受查询超时控制。已发送请求后等待响应的超时不会授权切换路径。
- NTLM/Kerberos/Negotiate、自动读取钥匙串及通过删除默认路由实现防火墙级隔离仍不在当前能力范围。Windows 不支持 `file:` PAC，macOS 未验证该方式。
