# 当前环境可执行的验收补充

## 范围与安全边界

本次补齐安装包归档检查、恢复存储预检、Linux GIO/PAC 故障和调度压力测试。只使用临时文件、私有 D-Bus/配置、loopback PAC 服务和模拟路由操作。未执行真实路由删除/恢复、系统代理更改、网卡切换或 DNS 更改。

这批是可重复的自动化验收，不代替真实桌面、网络切换、睡眠唤醒或长期运行验收。当前没有 macOS 和完整 Linux 桌面测试环境。

### 恢复预检新增覆盖

- 截断 JSON、旧格式版本、空路由及非默认路由快照均拒绝，原始字节保留，无探针遗留。
- 16 个并发工作协程各执行 10 次有效快照存储探测，原快照不被替换，临时探针全部清理。
- Linux 实际普通用户将临时恢复目录设置为不可写；删除/恢复两种预检均返回权限错误，仍保留完整快照。root 下该用例明确跳过，避免伪造权限覆盖。
- 这些是恢复存储检查，不能证明真实恢复的接口绑定、路由冲突或有效期校验已完成端到端验收；Windows ACL 真实拒写场景也未新增原生验收。

### 调度压力新增覆盖

- 同一 Manager 连续重启 200 次，同时读取健康状态和切换关闭自动保护；每个旧查询在取消后返回模拟成功结果，不覆盖新运行，结束后无未退出查询，不执行路由操作。
- 10,000 轮普通错误、超时、代理不可用和成功交替检查，成功清除查询失败计数，但保留独立路由失败状态。
- 此处为加速压力，不将“10,000 轮”表述为数小时/数日真实运行，也未完成 GUI、睡眠唤醒或内存长期增长验收。

## CI 归档检查

原生工作流已在上传前新增校验步骤：每个平台先运行校验器测试，再对实际 CLI/GUI 压缩包运行 `scripts/verify-native-artifacts.py`。

检查归档路径与重复成员、ZIP CRC、包内二进制格式/目标架构、Unix 所有者执行权限、Linux 两种包均包含同目录助手、macOS `.app` 的入口 plist。为每个内层压缩包记录 SHA256，结果上传为证据 Artifact 中的 `archive-check.json`，不解压或执行包内程序。

本批原生 CI 待提交推送后记录实际运行链接和结论。CI 归档校验通过只能证明 runner 上生成的归档；本地下载完整性、目标机依赖、实际启动和签名仍需分别验收。
