# 网络和代理切换严重问题修复清单

**本轮更新：** 原先部分修复的断网续作和路由恢复已补充代码；最新 8 项审查任务均已调整，待回归。下方基于 `763ce58` 的状态保留为历史记录，当前进展以 [修复进展](proxy-route-repair-progress.md) 为准。

状态更新至提交 `763ce58`。下文保留修复前问题说明；“已修复”表示原问题已有代码修复与既有回归依据，不表示真实切网和断网恢复已全部验证。当前限制见 [代码审查报告](proxy-route-code-review.md)，后续安排见 [修复计划](proxy-route-repair-plan.md)。

原清单包含六类问题，当前四类已修复、两类部分修复。P0 表示可能误断网；P1 表示可能使检测或断网保护失效。

## [已修复] P0 停止监控和任务重启缺少隔离

**当前状态：** 每轮运行使用独立 context 和任务身份；停止取消查询，旧任务不能清空或取消新任务；执行保护前核对当前任务。已有模拟及竞态回归依据。已执行的系统操作不能因停止而自动撤销，恢复记录会保留。

**影响：** 用户点击停止后，尚未完成的查询仍可能返回命中区域的结果并删除默认路由。快速停止再启动时，旧任务还可能清空新任务的运行状态或取消新任务。

**依据：** 停止后仍调用模拟删除函数已复现；旧任务干扰新任务由调用顺序确认。

**位置：** `internal/guiapp/monitoring/manager.go` 的 `Stop`、`run`、`checkOnce`、`requestStop`、`finishRun`；`internal/ipchecker/checker.go` 的查询 context。

**修复要求：** 将任务取消信号传入 HTTP 查询；结果处理和删除路由前检查任务是否仍有效；每次启动使用独立任务标识与取消函数，旧任务不能修改新任务状态。

**验收：** 查询进行中停止，随后返回区域匹配结果，不得删除路由；连续停止再启动，旧任务返回和退出均不得影响新任务。

## [已修复] P0 切换前的查询结果可能触发切换后的断网

**当前状态：** 查询前后、删除前及备份准备结束时核对网络与代理状态；Windows 路由/接口变化通知参与版本检查，失效结果返回 `network_changed`。已有模拟回归，真实切网与操作期间竞争仍有验证边界。

**影响：** 查询开始后用户切换网络、关闭代理或更换代理地址，旧请求返回的 IP 仍按原流程执行区域判断，可能据此删除当前新网络的默认路由。

**依据：** 代码只在查询开始时读取代理配置，执行路由操作前没有确认结果是否仍属于当前网络和代理。该风险尚未进行真实切网复现。

**位置：** `internal/monitor/monitor.go` 的 `CheckProxyStatusResult`；`internal/guiapp/monitoring/manager.go` 的 `checkOnce`。

**修复要求：** 查询结果关联任务与网络、代理配置版本；变化后废弃旧结果并重新检测；删除路由前重新确认上下文有效。是否增加稳定等待或连续匹配次数属于后续策略选择。

**验收：** 请求进行中切换代理或默认网络，旧结果不得直接触发新网络的断网操作。

## [已修复] P1 Windows 无法识别代理连接被拒绝

**当前状态：** 使用连接阶段的类型化错误识别，不再比较不兼容的系统常量；已验证本地端口关闭与重启。逐网址规则模式允许其他 API 继续按各自路径查询，不承诺因一个网址的代理失败而停止整轮。

**影响：** 用户退出代理进程后，当前代码继续将代理端口故障算作 API 失败，上一轮新增的等待与日志去重分支不能处理用户提供的 Windows 日志。

**依据：** 已通过 Windows 本地关闭端口复现：实际错误码 `10061`，当前判断常量 `syscall.ECONNREFUSED` 为 `536870934`，`errors.Is` 返回 false。

**位置：** `internal/ipchecker/checker.go:132`。

**修复要求：** 正确识别 Windows Socket 连接错误，同时确认失败发生在代理连接阶段；保留跨平台处理。代理链路失败不能处罚查询 API。

**验收：** 代理进程退出后，本轮停止无意义的 API 轮询，代理不可用日志去重，API 错误计数不增加；原端口重新可用后自动恢复查询。

## [已修复] P1 短暂断网可能导致监控永久失去查询能力

**当前状态：** 查询器不再永久删除；API 自身连续失败后冷却 30 秒再探测，网络故障不处罚 API，没有可用 API 时明确报错。已有长期故障恢复回归。

**影响：** 超时、连接重置等临时故障持续发生后，API 被从进程内注册表删除；网络恢复也无法重新使用。全部 API 被移除时，监控可能仍在运行，却持续查不到出口 IP。

**依据：** 已复现连续 11 次超时后查询器被移除；模拟服务恢复后依然返回空 IP。初始化只执行一次，停止再启动监控不会恢复查询器。

**位置：** `internal/ipchecker/checker.go` 的 `increaseErrorCount`、`initFetchers`、`GetExternalIP`。

**修复要求：** 区分网络故障、代理故障和 API 自身故障；用可恢复的退避或冷却代替永久删除；全部 API 暂不可用时返回明确错误并保留探测恢复能力。

**验收：** 长时间断网或代理上游中断后恢复，无须重启程序即可重新获得出口 IP；API 全部暂不可用时不能返回空 IP 加 nil 错误。

## [部分修复] P1 删除路由失败后保护不再执行或提前结束

**已修复：** GUI 仅在删除成功后标记已处理；CLI 传递错误并继续监控，不再误报成功。

**未修复：** 重试仍依赖下一轮成功查询并命中区域；部分路由已删除导致 API 不可达时，剩余删除可能无法继续。见 [审查报告第一项](proxy-route-code-review.md)。

**影响：** GUI 在删除成功之前就设置已处理标记，失败后持续命中区域也不再重试。CLI 在删除失败后仍可能停止监控，并输出网络已中断，实际保护没有完成。

**依据：** GUI 已复现连续两次命中区域却只尝试删除一次；CLI 行为由代码路径确认。

**位置：** `internal/guiapp/monitoring/manager.go:178`；`internal/monitor/monitor.go` 的 `CheckProxyStatus` 与 `StartMonitoring`。

**修复要求：** 成功后才标记处理完成；错误结果传递到上层；失败时保留监控，并依据失败类型提示处理或受控重试；仅在确认删除成功后报告断网完成。

**验收：** 第一次删除失败、随后条件允许时仍能完成保护；GUI 和 CLI 都不得在失败后显示断网成功或默默放弃保护。

## [部分修复] P1 路由保存删除恢复没有绑定具体网络

**已修复：** 统一保存所有网卡双栈默认路由及接口/网络信息，按记录操作，恢复前核对绑定，部分失败保留备份。

**未修复：** 持久路由创建参数、同身份路由属性更新后的冲突、无关地址变化阻止恢复，以及非 Windows 回退等风险仍在。不能将完整快照已实现等同于完整恢复已可靠。见 [审查报告](proxy-route-code-review.md)。

**影响：** 切网后恢复操作仍可能使用旧网关；多网卡场景保存的是其中一条默认路由，删除命令却没有限定相应接口与网关，可能影响多个网络，恢复也不一定能还原原状态。

**依据：** 静态代码确认：Windows 使用 `route delete 0.0.0.0`；恢复仅传入缓存网关，没有使用保存的接口信息或验证当前网络。尚未执行真实多网卡路由实验。

**位置：** `internal/iproute/route.go` 的 `GetDefaultRoute`、`DeleteDefaultRoute`、`AddDefaultRoute`；`internal/guiapp/actions.go` 的 `RestoreDefaultRoute`。

**修复要求：** 保存并识别具体路由、接口与网络身份；删除与恢复明确作用于目标路由；恢复前验证旧网络是否仍适用，避免直接向新网络添加旧网关。

**验收：** 双网卡、VPN 或 TUN 并存时，不误操作无关路由；从网络 A 切到 B 后，恢复操作不得直接套用 A 的网关。
